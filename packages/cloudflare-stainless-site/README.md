# cloudflare-stainless-site

Generates `cloudflare-api-site`'s data ported from the retired Stainless API
reference:

- `src/stainless-redirects.json`: the old site's pages, which the site redirects
  to today's (see its README's "Stainless redirects");
- `src/stainless-snippets.json`: its TypeScript, Python and Go samples, which the
  site shows as its SDK samples (see its README's "Stainless snippets").

This package is temporary. Delete it once Forge generates its own SDK samples and
the old site's redirects are retired.

## Contents

| Path                                      | What it is                                                         |
| ----------------------------------------- | ------------------------------------------------------------------ |
| `scripts/generate-stainless-redirects.ts` | The redirects generator, run by the `generate:redirects` script    |
| `scripts/generate-stainless-snippets.ts`  | The snippets generator, run by the `generate:snippets` script      |
| `scripts/gitlab.ts`                       | Downloads the inputs: the only part that uses the network          |
| `scripts/redirects.ts`                    | Turns them into the redirects snapshot, and compares two snapshots |
| `scripts/snippets.ts`                     | Turns them into the snippets file, and the format of that file     |
| `scripts/zip.ts`                          | Reads one file from a zip archive                                  |

The package exports nothing. The site reads both files with its own code;
`format` versions the snippets file's contract.

## Generating

You need access to the source and a token for it. Generate the redirects first:
the snippets generator keeps the method pages the snapshot holds. From the
repository root:

```sh
GITLAB_TOKEN=<token> pnpm generate:stainless-redirects \
  --gitlab-url https://<gitlab host> --project <group>/<project>
GITLAB_TOKEN=<token> pnpm generate:stainless-snippets \
  --gitlab-url https://<gitlab host> --project <group>/<project>
```

Both read the artifacts of the Stainless docs site's newest successful pipeline:
the snippets generator its TypeScript, Python and Go SDK JSON, and the redirects
generator its HTTP SDK JSON and the spec it was built from. The redirects
generator also reads the model redirects in the site's repository
(`api-redirects.json`). Downloads are cached in
`node_modules/.cache/stainless-snippets`.

- **The redirects generator** compares its snapshot with the committed one
  before replacing it, and prints how many pages and operationIds it adds and
  removes, and how many methods now map to another operationId. Add
  `--verbose` to list them, and review them before committing.
- **The snippets generator** keeps the snippets of the method pages in the
  snapshot, so the site can follow its redirects to today's page, and skips the
  rest. Add `--verbose` to list the pages skipped, and the old pages left without
  a snippet in a language.

Both fail if their output contains the GitLab host or its domain. They run with
an 8 GB heap, and nothing they read is executed. The files are committed and
regenerated by hand: no workflow runs them, because CI can't reach the source.

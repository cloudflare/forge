# cloudflare-terraform-docs

Generates Terraform documentation data from the released Cloudflare Terraform provider: for each
resource and data source, its attributes, HCL example and import command, and the API operations
it calls. `cloudflare-api-site` renders it next to the API reference.

This package is temporary: the provider is generated by Stainless. Delete it once Forge supports
Terraform natively (see `cloudflare-api-site`'s README for the full removal).

## Contents

| Path                                 | What it is                                                                         |
| ------------------------------------ | ---------------------------------------------------------------------------------- |
| `scripts/generate-terraform-docs.ts` | The generator, run by the `generate` script                                        |
| `scripts/sources.ts`                 | Clones the provider and cloudflare-go sources: the only part that uses the network |
| `scripts/terraform-provider.ts`      | Parsers for the provider's docs and service code, and cloudflare-go `api.md`       |
| `scripts/source-tree.ts`             | Confined, read-only access to the cloned sources                                   |
| `scripts/schema.ts`                  | The format of the generated file, which the output is validated against            |

The package exports nothing, and neither it nor the site depends on the other: the repository
root's `generate:terraform-docs` script runs the generator with the site's
`src/generated/terraform-docs.json` as `--output`. The site reads that file with its own schema,
and `format` versions the contract between the two.

## Generating

From the repository root:

```sh
pnpm generate:terraform-docs                            # regenerate for the provider version in the file
pnpm generate:terraform-docs --provider-version latest  # or a version such as 5.28.0
pnpm generate:terraform-docs --check                    # verify the committed file instead
```

The generator clones the provider at `v<version>`, and the cloudflare-go versions its `go.mod`
requires, into `node_modules/.cache/terraform-docs`, and reuses them on later runs. `latest` is
the newest stable version on the Terraform registry.

`scripts/sources.ts` is the only part that uses the network, and `git clone` is the only process it
runs. The clones are data: symbolic links are checked out as plain files, and tags must be release
tags. Everything else is offline and read-only, and a test enforces that. The sources are read
through `scripts/source-tree.ts`, which refuses symbolic links and paths outside each checkout, and
nothing in them is executed. It reads:

- `docs/{resources,data-sources}/*.md` (tfplugindocs output, the same content as the Terraform
  Registry) for descriptions and Required / Optional / Read-only attributes;
- `examples/` for HCL and import syntax;
- `internal/services/*` client calls plus cloudflare-go `api.md` to link each declaration to the
  API operations it calls (create, read, update, delete, import);
- `internal/version.go` and `.git/HEAD` to record the versions and commits used.

The parsers are strict. Unexpected Markdown fails with `file:line`, and so does an SDK call that
can't be resolved. The output is validated against `scripts/schema.ts` before it's written.
`.github/workflows/sync-terraform-docs.yml` runs the same command daily and opens a PR when a new
provider release is published. Untrusted sources are only handled in a job with read-only
permissions and no secrets.

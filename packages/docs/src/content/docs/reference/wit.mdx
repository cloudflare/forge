WebAssembly plugins are components of the `plugin` world in the `forge:plugin` package. The world
exports `generate`, which the host calls with the whole model as one `forge` record.

This page summarizes the interface: how to read it, the record and the worlds. The complete file,
with every record and its doc comments, is printed by `forge-plugin wit`, ships in the package as
`@cloudflare/forge/plugin/forge.wit`, and is `forge::wasm::WIT` in Rust. The meaning and order of every field are as the
[Rust API](/reference/rust-api/) documents them. The WIT is the same model, flattened into ids and
records.

## How to read it

- Every group, method, model and type is a `u32` id: its index in the matching list of the `forge`
  record, counting from 0. A part's record has everything the part has, with ids for its parts.
- `group-order` has every group id, depth first, starting with the root, which is group 0. The
  root's `name` and `path` are empty.
- A name is its lower-case words.
- JSON is its text, which `JSON.parse` reads back.
- A method's `params` is the object type of its path and query parameters, and `locations` says
  where each of that object's leading fields is sent, in field order. Together they are
  `Method::location`.

## The record

The `forge` interface has only types. Its last one is the record a plugin receives:

```wit
interface forge {
    // ... the id types and the records of each part ...

    /// A parsed document with all groups, methods, models and types indexed by id.
    record forge {
        info: forge-info,
        /// Every group id, depth first, starting with the root (0).
        group-order: list<group-id>,
        groups: list<group-info>,
        methods: list<method-info>,
        models: list<model-info>,
        types: list<type-info>,
    }
}
```

## The plugin world

What a plugin is: it exports the one function the host calls, and imports no functions from Forge:

```wit
world plugin {
    use forge.{forge};

    /// A generated file: its path relative to the output directory, using
    /// `/` as a separator, and its content. A file with no content is not
    /// written.
    record file {
        path: string,
        content: list<u8>,
    }

    /// Generates every file for `forge`, in a fresh instance. Called exactly
    /// once.
    export generate: func(forge: forge) -> result<list<file>, string>;
}
```

## The library world

The same file has a second world, `library`, which exports the `parser` and `normalizer` interfaces.
`parser.parse` takes an OpenAPI document as JSON text and returns the same `forge` record.
`normalizer.normalize` rewrites compatibility-mode extensions into Forge's native `x-forge-*` keys
and returns the rewritten JSON text. `parse` and `normalize` in `@cloudflare/forge` are built from
it. Refer to [Read a document in JavaScript](/guides/parse/).

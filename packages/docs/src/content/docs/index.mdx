Forge reads an OpenAPI document into one typed, language-neutral model, then hands that model to a plugin that writes the files. The generators that ship with Forge are plugins too, so one you write gets the same model they do.

It is for teams that publish an API on more than one surface: an SDK, the tools of an MCP server, a server that exposes the SDK, or something only your API needs.

## How it works

Forge does the shared part once: it reads the document, follows every `$ref`, and decides what is a group, a method and a model. A plugin does the part that belongs to one language. [The pipeline](/concepts/pipeline/) has each step and what it guarantees.

## Generate something

Forge is one native binary in an npm package. Install it:

<PackageManagers pkg="https://pkg.pr.new/cloudflare/forge/@cloudflare/forge@main" dev />

Point it at a document and pick a target:

<PackageManagers type="exec" pkg="forge" args="openapi.json --target ts --out sdk" />

That writes a TypeScript SDK to `sdk/`. [The quickstart](/start/quickstart/) walks through its output, and generates MCP tools from the same document.

## Write your own

A plugin is one function, `generate`, which takes the model and returns files. This one writes a list of method names for each group:

```ts title="plugin.ts"
import { definePlugin } from '@cloudflare/forge/plugin';

export const { generate } = definePlugin({
  generate(forge) {
    return forge.groups.map((group) => {
      const names = group.methods.map((m) => m.name.camel());
      const path = [...group.path.map((name) => name.kebab()), 'methods.txt'].join('/');
      return { path, content: names.join('\n') };
    });
  },
});
```

Compile it to a WebAssembly component:

<PackageManagers type="exec" pkg="forge-plugin" args="build plugin.ts --out plugin.wasm" />

Then run it as a target:

<PackageManagers type="exec" pkg="forge" args="openapi.json --target wasm://plugin.wasm --out out" />

[The plugin guide](/plugins/overview/) covers the model, testing and the other languages.

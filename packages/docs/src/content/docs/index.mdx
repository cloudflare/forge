## Why Forge

Every API needs more surfaces than it used to: an SDK per language, a CLI, an MCP server for agents,
reference docs, and whatever your users' favourite framework wants next. Forge is the pipeline for
all of them. It does the hard, shared part once (reading the document, following every `$ref`,
deciding what is a method and what is a model) and leaves the language-specific part to plugins.

<Features />

## Generate something in a minute

Forge ships as one native binary, wrapped in an npm package. Install it, point it at a document and
pick a target:

```sh
npm install --save-dev https://pkg.pr.new/cloudflare/forge/@cloudflare/forge@main
npx forge openapi.json --target ts --out sdk
```

That writes a TypeScript SDK: one directory per group, a typed client per directory, and a small
runtime. Swap `--target ts` for `--target mcp` and you get a Rust crate for an MCP server instead.

## Or write your own generator

A plugin is two functions: one called once for the whole document, and one called for each group,
in parallel. Here is a complete plugin, in TypeScript, that writes a Markdown file per group:

```ts
import { definePlugin } from '@cloudflare/forge/plugin';

export const { generate, generateGroup } = definePlugin({
  generateGroup(group) {
    const rows = group.methods.map((m) => `- \`${m.name.camel()}\`: ${m.httpMethod} ${m.path}`);
    return [{ path: `${group.path.map((n) => n.kebab()).join('/')}.md`, content: rows.join('\n') }];
  },
});
```

Compile it to a WebAssembly component and run it like any other target:

```sh
npx forge-plugin build plugin.ts --out plugin.wasm
npx forge openapi.json --target wasm://plugin.wasm --out docs
```

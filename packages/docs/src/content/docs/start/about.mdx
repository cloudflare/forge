Forge is a schema-first code generator built around one typed, language-neutral API model. It hands
that model to **plugins** that write files: SDKs, CLIs, MCP servers, documentation, or anything else
you can derive from an API description.

It is open source under the Apache 2.0 license, and it is what Cloudflare uses to generate the
surfaces of its own API, starting with the [`cf` CLI](https://blog.cloudflare.com/cloudflare-cf-cli-launch/).

## The problem

An API with thousands of operations, owned by hundreds of teams, needs the same set of surfaces kept
in step with every change: an SDK per language, a CLI, an MCP server, reference docs. Generators
exist for each of those, but each one re-reads the API description its own way, disagrees with the
others about edge cases, and is hard to extend past the targets its authors chose.

Forge splits the work in two:

- **The shared part** is done once, in Forge's core. It reads the API description, follows every `$ref`,
  decides which operations are methods and how they are grouped, turns schemas into types, places
  each model in the group that uses it, and reports every problem in the input at once.
- **The language part** is done by plugins. A plugin does not parse the source format. It sees
  groups, methods, models and types, and returns a list of files.

## Pluggable by design

The generators that ship with Forge are plugins. The TypeScript SDK and the MCP server implement
the same `Plugin` interface that you will, and read the same model through the same API. There is
no privileged internal representation that only built-in targets can reach.

You can write a plugin two ways:

- **As a WebAssembly component**, in any language that builds one. For TypeScript and JavaScript,
  `forge-plugin build` does it for you. You run it with `--target wasm://plugin.wasm`.
- **In Rust, against Forge as a library**, in a binary of your own.

A WebAssembly plugin cannot read files, reach the network or see the environment. It gets the model
and returns files, and Forge writes them, only under `--out`. Refer to
[Plugins](/plugins/overview/).

## Inputs: today and direction

Today, Forge accepts one bundled [OpenAPI](https://spec.openapis.org/oas/latest.html) 3.0, 3.1 or
3.2 document as JSON. It does not accept YAML, AsyncAPI, other API description formats or multiple
source files. Convert YAML to JSON and bundle external references before running Forge.

The model is a boundary between reading an API description and generating output. Forge intends to
add readers for AsyncAPI and other specifications, and to accept multiple source files. That is a
direction, not current support. New kinds of API description may also require the model and plugin
interface to grow.

## Current OpenAPI support

Forge reads all three versions into the same model, so a plugin never needs to know which one a
document was written in. Where the versions differ, Forge follows each one's rules:

- **Next to a `$ref`**, 3.0 ignores every other keyword, except a few of Forge's own, such as
  `x-forge-sensitive`. From 3.1, Forge reads them: a
  `description`, `default`, `readOnly` or `nullable` beside a `$ref` applies to that use of it.
- **Nullable values** are written `nullable: true` in 3.0 and as a list of types with `null` in 3.1.
  Forge reads both, in every version, as the same nullable type.
- **3.2** adds the `QUERY` method, `additionalOperations`, `in: querystring` parameters and a
  discriminator's `defaultMapping`, and Forge reads each of them.

[What Forge reads](/openapi/support/) lists every keyword.

## What exists today

Forge is early. It is being built for Cloudflare's own SDKs first and opened up as it goes, so
expect the model and the plugin interface to grow.

Today:

- **Input:** one bundled OpenAPI 3.0, 3.1 or 3.2 document, as JSON.
- **Built-in targets:** a TypeScript SDK (`ts`), which is experimental, a Cap'n Web server over that
  SDK (`capnweb`), and the tools of an MCP server, in TypeScript (`mcp`).
- **Plugins:** WebAssembly components against a published WIT, with first-class libraries for
  TypeScript authors, and native plugins in Rust.
- **A JavaScript library:** `parse` from `@cloudflare/forge` reads a document into the same model,
  in your own process. Refer to [Read a document in JavaScript](/guides/parse/).

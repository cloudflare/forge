Most of the work in generating TypeScript is not the code, it is the imports: which file declares
each type, what the relative path is from here, whether to `import type`, and what to do when two
names clash. `@cloudflare/forge/ts` does all of that. You print lines that mention **identifiers**,
and the file works out its imports when it renders.

It is the JavaScript version of `forge::ts`, the Rust printer the built-in TypeScript target uses,
and renders the same text.

```ts
import { file, module } from '@cloudflare/forge/ts';

const models = module('pets/models.ts');
const f = file('pets/client.ts');
f.doc('A client of pets.');
f`export interface ${f.ident('Client')} {`;
f.indent(() => {
  f`get(): Promise<${models.ident('Pet').ty()}>;`;
});
f`}`;
```

renders as:

```ts
// Code generated by forge. DO NOT EDIT.
/* eslint-disable */

import type { Pet } from "./models.js";

/**
 * A client of pets.
 */
export interface Client {
  get(): Promise<Pet>;
}
```

## Modules

A **module** is something a file can import from. A path ending in `.ts` is a generated file, named
from the output directory; anything else is a package, imported by its specifier unchanged.

```ts
module('pets/models.ts');   // a generated file, imported as "./models.js" or "../pets/models.js"
module('zod');              // a package, imported as "zod"
module('node:fs');
module.ROOT;                // the output directory
module.ROOT.sub('index.ts');            // "index.ts"
module.group(group);                    // "accounts/members": the group's directory
module.group(group).sub('client.ts');   // "accounts/members/client.ts"
```

`module.group` names each directory after the group's name in camel case, with a `_` in front if it
starts with a digit, so a group `list_all` inside `pet-store` is `petStore/listAll`.

## Identifiers

An **identifier** is a name and the module that declares it. Printing one from another module
imports it.

```ts
const z = module('zod').ident('z');
const pet = module('pets/models.ts').ident('Pet');
pet.ty();            // the same, but only a type: imported with `import type`
pet.as('PetModel');  // imported as `Pet as PetModel`
module('temporal-polyfill').ident('Temporal.Instant');  // imports `Temporal`, prints `Temporal.Instant`
f.ident('Client');   // declared in this file: never imported
```

`ident.model(model)` is the identifier the built-in target uses for a model: its name in Pascal case
in the `models.ts` of its group, or of the root. A [model](/concepts/models/) can also be printed
directly, and prints as that identifier.

## Printing

Call the file as a tagged template to print a line. Interpolate strings, numbers, identifiers,
models, or arrays of them.

```ts
f`export const ${f.ident('baseUrl')} = ${JSON.stringify(forge.baseUrl)};`;
f();                          // a blank line
f('let pet: ', pet, ';');     // the same as a template, for parts built at run time
f.doc(method.description);    // a JSDoc comment, wrapped at 80 columns
f.indent(() => { /* ... */ }); // two more spaces for what is printed inside
```

For a piece of a line that you build first and print later, use `` frag`...` ``, and for a list with
separators, `join`:

```ts
import { frag, join } from '@cloudflare/forge/ts';

const list = frag`Promise<${pet}[]>`;
f`list(): ${list};`;

f`type Any = ${join(' | ', members.map(ts))};`;
```

`join` leaves out parts that print nothing, so `join(', ', ['a', '', 'c'])` is `a, c`.

Interpolating anything else, such as `undefined` or an object of your own, throws, instead of
printing `undefined` or `[object Object]`. Use `String(x)` for a value you mean to print.

## Rendering

A `File` is already a plugin file: it has `path` and `content`, so return it from `generate` or
`generateGroup` as it is. Its content is:

1. the preamble, `// Code generated by forge. DO NOT EDIT.` and `/* eslint-disable */`;
2. the imports: packages first, then a blank line, then generated files, each sorted by specifier,
   one declaration per module, `import type` when every name from a module is only a type, on one line if it fits in 80
   columns;
3. the lines you printed.

A file with nothing printed renders as nothing, and so is not written. If an imported name clashes
with one the file declares, or an earlier import, it gets `$` appended.

## Example: Zod schemas

This plugin writes a `schemas.ts` per group with a [Zod](https://zod.dev/) schema for each model,
and refers between them across files:

```ts title="zod.ts"
import { definePlugin, type Model, type Type } from '@cloudflare/forge/plugin';
import { type File, type Module, type Part, file, frag, join, module } from '@cloudflare/forge/ts';

const z = module('zod').ident('z');

/** The identifier of a model's schema, in the `schemas.ts` of its group. */
function schemaOf(model: Model) {
  const dir = model.group ? module.group(model.group) : module.ROOT;
  return dir.sub('schemas.ts').ident(`${model.name.pascal()}Schema`);
}

function zod(type: Type): Part {
  switch (type.kind) {
    case 'scalar':
      switch (type.scalar) {
        case 'null': return frag`${z}.null()`;
        case 'boolean': return frag`${z}.boolean()`;
        case 'number': return type.number === 'int64' ? frag`${z}.bigint()` : frag`${z}.number()`;
        case 'date-time': return frag`${z}.iso.datetime()`;
        case 'date': return frag`${z}.iso.date()`;
        case 'unknown': return frag`${z}.unknown()`;
        default: return frag`${z}.string()`;
      }
    case 'enum':
      return frag`${z}.literal([${join(', ', type.values.map((v) => JSON.stringify(v)))}])`;
    case 'array':
      return frag`${z}.array(${zod(type.elem)})`;
    case 'object': {
      const fields = type.fields.map((f) => {
        const value = f.required ? zod(f.type) : frag`${zod(f.type)}.optional()`;
        return frag`${JSON.stringify(f.wireName)}: ${value}`;
      });
      return frag`${z}.object({ ${join(', ', fields)} })`;
    }
    case 'union':
      return frag`${z}.union([${join(', ', type.members.map(zod))}])`;
    case 'intersection':
      return type.members.map(zod).reduce((a, b) => frag`${z}.intersection(${a}, ${b})`);
    case 'model':
      // Lazily, so models can refer to each other, or to themselves, in any order.
      return frag`${z}.lazy(() => ${schemaOf(type.model)})`;
  }
}

function schemas(dir: Module, models: readonly Model[]): File {
  const f = file(dir.sub('schemas.ts'));
  for (const model of [...models].sort((a, b) => a.schemaName.localeCompare(b.schemaName))) {
    f.doc(model.description);
    f`export const ${schemaOf(model).name} = ${zod(model.type)};`;
  }
  return f;
}

export const { generate, generateGroup } = definePlugin({
  generate: (forge) => [schemas(module.ROOT, forge.models)],
  generateGroup: (group) => [schemas(module.group(group), group.models)],
});
```

For a group `a.b` whose model `Member` refers to `Status`, which is placed in `a`, the output
imports it:

```ts title="a/b/schemas.ts"
// Code generated by forge. DO NOT EDIT.
/* eslint-disable */

import { z } from "zod";

import { StatusSchema } from "../schemas.js";

/**
 * A member.
 */
export const MemberSchema = z.object({ "id": z.string(), "status": z.lazy(() => StatusSchema).optional() });
```

The declarations print `schemaOf(model).name`, a plain string. Printing `schemaOf(model)` itself
would work too: a file never imports an identifier whose module is the file.

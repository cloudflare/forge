`parse` from `@cloudflare/forge` reads one bundled OpenAPI JSON document into
[the model](/concepts/the-model/) in your own process. It does not bundle or combine source files.
It returns the same `Forge` a [TypeScript plugin](/plugins/typescript/) receives, with the same
groups, methods, models and types. Use it when a tool needs the model but does not generate files,
such as a docs site that lists an API's methods.

It runs Forge compiled to WebAssembly, so it needs neither the `forge` binary nor a plugin.

## Prerequisites

- Node.js 18 or later.
- A document to read, such as the pet store document from
  [Get started](/start/get-started/#1-write-a-document), saved as `openapi.json`.

## 1. Install the package

`parse` is the main export of Forge's package:

<PackageManagers pkg="@cloudflare/forge" dev />

## 2. Parse a document

`parse` takes the document as JSON text, and returns its `Forge`. This script prints every method:

```js title="routes.mjs"
import { readFile } from 'node:fs/promises';
import { parse } from '@cloudflare/forge';

const forge = parse(await readFile('openapi.json', 'utf8'));
for (const group of forge.groups) {
  for (const method of group.methods) {
    console.log(method.httpMethod, method.path, method.name.camel());
  }
}
```

Run it:

```sh
node routes.mjs
```

It prints the three methods of the pet store document:

```text
POST /pets create
DELETE /pets/{pet_id} delete
GET /pets list
```

Every type and property of the result is in the [Plugin API](/reference/plugin-api/#the-model).
`@cloudflare/forge` exports the same model types as `@cloudflare/forge/plugin`. Each call returns a
separate Forge model. Several documents can be read side by side, such as one for each version of an
API, but they are not combined into one model.

## Errors

`parse` throws an `Error` when Forge cannot read the document, with the message the `forge` command
prints after `forge: ` and the file name. A document with no `openapi` key, such as a Swagger 2.0
document, throws:

```text
the document has no openapi version: only OpenAPI 3.0, 3.1 and 3.2 are read
```

Refer to [Troubleshooting OpenAPI documents](/openapi/errors/) for each message.

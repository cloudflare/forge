# cloudflare-stainless-snippets

Ports the retired Stainless API reference's TypeScript, Python and Go samples into
`cloudflare-api-site`'s `src/stainless-snippets.json`. The site shows them as its
SDK samples (see its README's "Stainless snippets").

This package is temporary. Delete it once Forge generates its own SDK samples.

## Contents

| Path                                     | What it is                                                   |
| ---------------------------------------- | ------------------------------------------------------------ |
| `scripts/generate-stainless-snippets.ts` | The generator, run by the `generate` script                  |
| `scripts/gitlab.ts`                      | Downloads the snippets: the only part that uses the network  |
| `scripts/snippets.ts`                    | Turns them into the site's file, and the format of that file |
| `scripts/zip.ts`                         | Reads one file from a zip archive                            |

The package exports nothing. The site reads the file with its own schema, and
`format` versions the contract between the two.

## Generating

You need access to the source and a token for it. From the repository root:

```sh
GITLAB_TOKEN=<token> pnpm generate:stainless-snippets \
  --gitlab-url https://<gitlab host> --project <group>/<project>
```

Add `--verbose` to list the pages skipped, and the old pages left without a
snippet in a language. The generator keeps the snippets of the method pages in
the site's `src/stainless-redirects.json`, so the site can follow its redirects
to today's page, and skips the rest. It fails if any snippet contains
the GitLab host or its domain. Downloads are cached in
`node_modules/.cache/stainless-snippets`.

It runs with an 8 GB heap. Nothing it reads is executed. The file is committed
and regenerated by hand: no workflow runs it, because CI can't reach the source.
